## Готово для A

- B0–B5 готовы; 32 теста прошли. Все вкладки проверены без API-ключа; Responses API — фейковым клиентом, без платных запросов.
- graf.evidence_xlsx.build_evidence готов. Все 6 листов, API записи файла и байтов выбранного узла проверены; gid — текст Excel.
- Все gid в браузерных форматах передаются строками, исходные данные/выгрузки A не меняются.

## Запросы к A

- Готовность chrono_reach распознаётся и с сигнатурой функции. Ползунок 1–31 подключён по статусу A.
- Новые A4/A5 опубликованы; обновление README и проверка свежих выгрузок — следующий шаг после фиксации B5.
- Исправлен Windows-тест пути (Path.name), временный статус пишется в UTF-8. B-тесты автоматически создают out_stub, если его нет.

## Решения, которые я принял сам

- При отсутствии готовности A1 в статусе A приложение по умолчанию использует out_stub;
  папку out можно явно выбрать для read-only проверки.
- Не ждать необязательных колонок: отображать «нет данных», а не придумывать признаки.
- README содержит запуск, формулы, ограничения и схему. tools/update_readme_results.py обновляет цифры только при готовом A4; до него плейсхолдеры.
- Скриншоты сделаны на реальном A3. Неполные дополнительные CSV дают сообщение, а не падение всего приложения.
- Git HTTPS не авторизован; подключённый GitHub API позволяет публиковать b-ui без изменения main.
  Объекты Git при синхронизации проверяются по SHA; опубликованная история не переписывается.
