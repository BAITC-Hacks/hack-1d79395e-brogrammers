## 3. Сценарий B-006

Прочитан B-006 из `origin/b-ui` (`6601877`). Реализованы существующими средствами приложения:

- Краткая сводка, причины приоритета, контр-сигнал и следующий запрос располагаются перед графом.
- XLSX текущего узла готовится и скачивается в карточке; смена узла или источника не должна возвращать предыдущий файл.
- Таблицы «Кто переводил на этот счёт» и «Кому переводил этот счёт» открывают карточки точных известных gid; есть возврат к предыдущему узлу.
- Список и карта показывают активные фильтры и число узлов; доступен явный сброс. Пустой топ не изображается как пустая исходная выгрузка.
- Возврат к списку сохраняет фильтры; скрытый ими выбранный узел сопровождается пояснением и явным действием показа.
- Понятные подписи «Исходные клиенты (seed)» и «Связи на расстоянии 1–2 переводов» дополнены подсказками.

Код и целевые регрессии готовы. Окончательная проверка после B-006: полный pytest — **105 passed за 72,01 с**; smoke — **health 200, 15 с без ошибки запуска**; живой браузер — **Живой браузер: поиск, Δ=2, входящий и исходящий контрагент, возврат, карта, сохранение фильтров, пустой топ, явный сброс скрывающих фильтров, подготовка и скачивание XLSX узла**.
Результат живого сценария и результат автоматических тестов фиксируются отдельно; наличие кода само по себе не считается подтверждением пройденной проверки.

## 5. Методические выводы и ограничения

Формула приоритета и её веса не менялись ради улучшения графика устойчивости. Brokerage остаётся долей потерянной достижимости по TEAM_PLAN §7.4, а не перцентилем. Очередь проверки не оптимизирует исключительно распад графа при блокировании.

Сравнение с одной случайной перестановкой заменено на **100 воспроизводимых испытаний** (`RANDOM_TRIALS=100`, seed генератора 42). В `resilience.csv` добавлены `n_trials`, `seed_reach_p05`, `seed_reach_p95`. Для random сохраняются среднее и эмпирические 5-й/95-й процентили исходов; это **не доверительный интервал среднего**. Внутри испытания разные N используют один порядок удаления. Детерминированные стратегии и ранги не изменены.

При N=50 сохранённая достижимость: priority **0,850023**, out_deg **0,491924**, betweenness **0,622981**, random в среднем **0,954135**, эмпирический диапазон 5–95% **0,914905–0,970028**. Это структурный эксперимент, не доказательство эффективности конкретного банковского вмешательства.

Доля исходящего оборота external_funding — 66,94%, топ-30 — 3,99%; метод ориентирован на приоритет проверки seed-потока. Двухузловые встречные переводы входят в структурный мотив cycle, а отсутствие выраженного мотива не заменяется выдуманной гипотезой. Высокий эвристический скор terminal не является вероятностью виновности или установленного удержания денег.

Остаются ограничения исходного кейса: только исходящие внутрибанковские переводы, июль 2026, порог 5000 ₸, обрыв четвёртого колена и даты без времени. Порядок внутри дня и фактическое происхождение средств по этим данным не устанавливаются. Сценарий масштабирования до ~1 млн узлов описан; на таком объёме текущая реализация не проверялась.

Git-объекты получены через авторизованный GitHub API, проверены по SHA, затем клонированы через временное зеркало. Обычная HTTPS/SSH-авторизация этим способом не проверялась.

B6 исторического SHA не объявляется проверкой чистого клона нынешней доработки. Тег `v1.0` не переписывается.

## 7. Публикация и оставшиеся действия команды

Текущий результат публикуется в `a-core` с обновлёнными `out/`, README, статусами и сообщением A-007 в `forB.md`. После коммита A проверяет свежие `origin/b-ui` и `forA.md`.
Обновление main выполняется после команды пользователя «финал ещё раз»; новую поставку следует идентифицировать её точным SHA и повторно проверить в чистом окружении.

`requirements-lock.txt` фиксирует установленное Windows / Python 3.12.14 окружение, проверенное `pip check`; отдельная чистая установка именно этого lock ещё не подтверждена. `tools/constraints-py312.txt` отражает окружение B и имеет описанную в README область применения. Публичная deployed-версия не заявляется.

Команде остаются репетиция/показ живого пятиминутного демо и подтверждение подачи решения на платформе. Автоматический аудит файлов не подтверждает выполнение этих внешних действий.
