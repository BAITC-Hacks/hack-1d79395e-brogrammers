## 7. Что не является дефектом

Приоритет проверки объединяет роль, прослеживаемые деньги, связность, объём и временные признаки.
Он не оптимизирует исключительно разрушение графа при удалении узлов.
После удаления 50 узлов доля seed-достижимости: priority 0,8500; out_deg 0,4919; betweenness 0,6230.
Поэтому превосходство out_deg в сценарии удаления не опровергает корректность очереди аналитической проверки.
Это разные цели; интерфейс и README должны сохранять такое пояснение.

Brokerage по §7.4 — доля потерянной достижимости: максимум 0,124135, медиана 0; в топ-30 максимум 0,012460. При N=23 остаток priority/random — 0,942317/0,919705; при N=50 — 0,850023/0,856945. Перевод в перцентиль изменяет метод и не принимается только ради победы над одной случайной выборкой RNG42.

External_funding дают 66,94% исходящего оборота, топ-30 — 3,99%; приоритет ориентирован на seed-поток, а не весь оборот. 39/46 циклов — встречные переводы двух узлов; 58/107 кластеров без выраженного мотива — допустимые результаты без выдумывания назначения. 860 terminal с одним входящим переводом и ≥средней уверенностью относятся к depth≤3; вместе с оценочными depth4 их 1188. Role_score — эвристика, не калиброванная вероятность преступной роли.

Отсутствие публичного deployment не нарушает ТЗ: локальный экран допускается.
Опциональный OpenAI API не нужен для pipeline/UI/XLSX; ключ и модель требуются только ассистенту.
Отсутствие ground truth не позволяет заявлять accuracy ролей; оцениваются правила, объяснения и полезность проверки.
Ограничения глубины, исходящих переводов, суммы ≥5000, одного банка и дат без времени нельзя устранить текущими данными.
